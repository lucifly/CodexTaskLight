## 数据流

```text
Codex 桌面端本地 IPC ── 快照 / 增量补丁 ──┐
                                       ├─ 状态归一化 ─ 自动选取任务 ─ 悬浮灯 / 详情

```

## 实时状态订阅

通过当前用户默认数据目录下的 `~/.codex/ipc/ipc.sock` 建立本地 Unix socket 连接。客户端初始化后，作为观察者订阅主任务状态。

当前实现适配内部状态协议 v11，处理完整快照、带版本号的增量补丁，以及所属桌面客户端断开等事件。补丁版本不连续时，会丢弃该任务的缓存并请求新的快照，避免继续显示不一致的等待状态。

保留的字段主要是运行状态及待处理请求。客户端不会发送任务启动、中断、确认批准、文件授权或配置修改请求。

连接断开后使用退避的一次性重连，期间显示未知状态。这不是对任务的周期性扫描。

## 文件事件与增量日志

通过 macOS FSEvents 的单个递归事件流监听 Codex 数据目录，筛选任务索引和日志变化，不为每个历史任务打开监听句柄。事件在短时间内合并处理；日志游标记录 inode、设备号和读取位置，正常追加时只读取新增字节。

任务列表额外使用至多三个 vnode 监听对象，分别关注数据根目录、最新 SQLite 索引和对应 WAL，及时发现归档等仅更新数据库的变化。这部分监听数量固定，不随任务数量增长；监听创建失败时显示未知并退避重试。

不完整的最后一行会保留到后续写入再解析。文件替换、截断、新目录和新任务出现时，会更新游标。系统报告事件丢失或目录事件合并时，会按事件触发索引与日志校准；监听根目录变化时会重建事件流。事件流启动失败时显示未知并退避重试，不会静默丢弃部分任务。初次加载会从日志尾部寻找生命周期记录，并设置读取上限；超出可识别范围时可能显示未知。

日志中的结构化异步问题会按请求编号与用户回复关联。工具返回明确失败、未接受或取消时，只移除对应请求的待答问题；正常结束一轮不会清除尚未回答的有效异步问题。普通聊天文本不用于猜测等待状态。

实时状态为 `idle` 只表示停止执行；如果日志已记录本轮失败或中断，会保留红灯。后续任务开始会重置日志状态，正常完成后可恢复绿灯。

当日志回退状态为执行中但长时间没有新记录时，使用一次性三分钟期限转为未知；这个期限不扫描文件，也不会覆盖可用的实时执行状态。

## 任务选取

详情面板支持自动与手动两种方式。自动模式使用以下规则：

1. 优先选择等待用户处理的主任务。
2. 没有等待任务时，选择执行中的主任务。
3. 没有执行中任务时，显示最近可识别的任务状态。
4. 同一优先级根据最近日志事件时间选择。

手动模式按保存的任务编号固定选择，使用相同的 IPC 与日志状态来源。所选目标不在本机未归档列表时，返回未知并提示重选，不自动跳到其他任务。候选列表来自已有事件驱动的任务缓存，切换选择不会引入周期性扫描。

任务显示名称优先使用索引的 `name` 自定义字段；该字段为空、仅含空白或旧索引没有此字段时，回退到 `title`。重命名触发索引监听后重新加载任务元数据，当前任务和候选列表使用同一份最新名称；不依赖日志追加，也不改变按任务编号保存的手动选择。

跟踪偏好保存在本机 `UserDefaults` 中；更新选择时通过串行监听队列发布新快照，界面忽略偏好版本不匹配的旧快照，防止切换期间显示其他任务的过期状态。

灰灯表示无法确认，不应解读为任务失败。实时空闲、日志完成和异常回退的表现可能受桌面端提供的状态字段影响。

## 界面与开销

悬浮窗使用非激活型 `NSPanel`，外框与灯珠使用固定 `CALayer`，状态变化仅更新颜色，关闭隐式动画。位置存放在应用的 `UserDefaults` 中。

经典与万圣节皮肤共享同一状态来源及 40 × 96 点窗口。万圣节图案由固定的 `CAShapeLayer` 路径绘制，切换时仅更新显隐、颜色和静态光晕；没有额外图片资源、循环动画或计时器。皮肤选择也存放在本机 `UserDefaults` 中。

空闲时主要等待 socket 和文件事件；任务频繁输出时仍需解析推送和新增记录。处理量会随任务数量、历史加载量和输出频率变化。仓库不承诺固定的 CPU 或内存上限。

## 兼容性边界

IPC、SQLite 表结构、日志事件和确认回复格式都来自桌面端内部实现，存在版本变化风险。本项目不提供官方支持保证；当前也不支持自定义 Codex 数据根目录、云端任务、其他电脑和子代理。
