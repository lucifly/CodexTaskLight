# 使用说明

[返回 README](../README.md)

## 启动与退出

从 [GitHub Release](https://github.com/lucifly/CodexTaskLight/releases/latest) 下载 `CodexTaskLight-v2.6-macOS-arm64.zip`，解压后将 `CodexTaskLight.app` 拖入「应用程序」文件夹。需要 Apple Silicon Mac；源码构建的应用位于 `dist/CodexTaskLight.app`。

先打开 Codex 桌面端，再打开 CodexTaskLight。应用只显示竖款悬浮窗，不创建菜单栏或 Dock 图标。

发布包使用 ad hoc 本地签名，未经过 Developer ID 签名或 Apple 公证，macOS 可能阻止首次打开。确认下载来源和 SHA-256 校验值后，可参考 [Apple 官方说明](https://support.apple.com/zh-cn/102445)，在尝试打开后通过「系统设置 → 隐私与安全性 → 仍要打开」为该应用单独允许启动。

右键悬浮窗，选择“退出 CodexTaskLight”即可结束运行。

## 悬浮窗操作

| 操作 | 结果 |
| --- | --- |
| 拖动悬浮窗 | 调整位置，松开后保存 |
| 点击悬浮窗 | 展开当前任务详情；再次点击可关闭详情 |
| 右键 → 查看任务详情 | 展开详情 |
| 右键 → 重置位置 | 回到当前屏幕右上方 |
| 右键 → 外观 | 切换经典或万圣节皮肤 |
| 右键 → 退出 CodexTaskLight | 退出应用 |

更换屏幕时，程序会尝试将窗口限制在可见区域。若窗口暂时看不到，再次打开应用可重新显示。

## 万圣节皮肤

在详情面板的“悬浮窗外观”，或右键菜单的“外观”中选择“万圣节 🎃”。从上到下分别是红色幽灵（等待确认、审批或异常）、橙色南瓜（执行中）、绿色蝙蝠（已完成）；未知状态显示灰色。

皮肤选择会在本地保存，重启后恢复。选择“经典红绿灯”可随时切回原样。两种皮肤使用相同的任务状态和窗口尺寸，万圣节图案使用固定矢量图层，不增加循环动画或计时器。

## 灯色与任务选择

- **红灯**：等待确认、审批或输入；也表示程序能识别的异常状态。具体含义以详情面板为准。
- **黄灯**：任务执行中。
- **绿灯**：本轮结束，不等于测试通过或用户的整体目标完成。
- **灰灯**：连接不可用、快照尚未到达，或当前状态无法确认。

自动模式下，多个任务并行时，等待你处理的任务优先；其次是正在执行的任务。在同一优先级内，程序根据最近的日志事件时间选择任务。全部停止执行后，显示最近可识别的任务状态。

## 手动指定任务

1. 点击悬浮灯，打开详情。
2. 将“跟踪方式”切换为“手动指定”。
3. 在搜索框输入任务名称，点击列表中的任务；勾选标记表示当前指定目标。
4. 需要恢复自动选择时，切回“自动识别”。

列表展示本机未归档的主任务，按任务索引的最近更新时间排列。手动模式固定跟踪所选任务，其他任务的状态变化不会抢占灯色。模式和上次手动选择会在本地保存，重启后恢复；切回自动模式也会保留上次手动目标，方便下次选择。

任务名称优先显示你在 Codex 中改过的自定义名称；未设置或名称为空时显示原标题。改名后会随索引变化更新详情、列表和搜索结果，固定跟踪的任务编号保持不变。

首次切换到手动模式时，需先选择任务。若所选任务已归档、被移除或不在当前本机列表中，会显示灰灯和重新选择提示；此时可选择另一个任务或切回自动模式。

## 等待确认的识别范围

原生审批依赖桌面端暴露的运行状态及待处理请求字段。异步确认问题通过结构化工具请求编号与回复编号关联；多个问题需要全部回答，才会解除该请求的等待状态。

普通聊天文本中的提问，不会仅凭一句“请确认”就被判定为等待。宿主未暴露或未来版本新增的请求类型，也可能无法识别。

解除等待后，通常恢复黄灯；如果任务随即结束，则会直接显示结束状态。

## 常见问题

### 一直是灰灯

确认 Codex 桌面端正在运行，而且当前用户可以访问默认 `~/.codex` 目录。仅运行 CLI 或改用了其他数据目录时，可能无法接入本机桌面状态流。

如果桌面端刚更新，也可能是内部协议变化。提交问题时请提供版本和复现步骤。

### 没有监控到云端任务

当前只支持本机主任务，不包含云端执行、其他电脑上的任务或子代理。

### 任务结束后仍显示某个任务

程序会保留最近可识别的状态；这不是仍在执行的提示。可以点击查看具体任务。

### 拖动或切换桌面时闪动

当前绘制使用固定图层并关闭隐式动画，但不同屏幕、系统版本和窗口管理软件仍可能影响显示。请记录触发动作及相关版本，并通过 Issue 反馈。

### 如何升级本地构建

先右键退出应用，再更新源码并运行 `./build.command`，最后重新打开应用。使用 Release 安装包时，先退出旧版，再用新包中的应用替换原应用。应用标识保持不变时，保存的位置会继续使用。
