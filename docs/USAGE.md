# 使用说明

[返回 README](../README.md)

## 启动与退出

先打开 Codex 桌面端，再打开 `dist/CodexTaskLight.app`。应用只显示竖款悬浮窗，不创建菜单栏或 Dock 图标。

右键悬浮窗，选择“退出 CodexTaskLight”即可结束运行。

## 悬浮窗操作

| 操作 | 结果 |
| --- | --- |
| 拖动悬浮窗 | 调整位置，松开后保存 |
| 点击悬浮窗 | 展开当前任务详情；再次点击可关闭详情 |
| 右键 → 查看任务详情 | 展开详情 |
| 右键 → 重置位置 | 回到当前屏幕右上方 |
| 右键 → 退出 CodexTaskLight | 退出应用 |

更换屏幕时，程序会尝试将窗口限制在可见区域。若窗口暂时看不到，再次打开应用可重新显示。

## 灯色与任务选择

- **红灯**：等待确认、审批或输入；也表示程序能识别的异常状态。具体含义以详情面板为准。
- **黄灯**：任务执行中。
- **绿灯**：本轮结束，不等于测试通过或用户的整体目标完成。
- **灰灯**：连接不可用、快照尚未到达，或当前状态无法确认。

多个任务并行时，等待你处理的任务优先；其次是正在执行的任务。在同一优先级内，程序根据最近的日志事件时间选择任务。全部停止执行后，显示最近可识别的任务状态。

## 等待确认的识别范围

原生审批依赖桌面端暴露的运行状态及待处理请求字段。异步确认问题通过结构化工具请求编号与回复编号关联；多个问题需要全部回答，才会解除该请求的等待状态。

普通聊天文本中的提问，不会仅凭一句“请确认”就被判定为等待。宿主未暴露或未来版本新增的请求类型，也可能无法识别。

解除等待后，通常恢复黄灯；如果任务随即结束，则会直接显示结束状态。

## 常见问题

### 一直是灰灯

确认 Codex 桌面端正在运行，而且当前用户可以访问默认 `~/.codex` 目录。仅运行 CLI 或改用了其他数据目录时，可能无法接入本机桌面状态流。

如果桌面端刚更新，也可能是内部协议变化。提交问题时请提供版本和复现步骤。

### 没有监控到云端任务

当前只支持本机主任务，不包含云端执行、其他电脑上的任务或子代理。

### 任务结束后仍显示某个任务

程序会保留最近可识别的状态；这不是仍在执行的提示。可以点击查看具体任务。

### 拖动或切换桌面时闪动

当前绘制使用固定图层并关闭隐式动画，但不同屏幕、系统版本和窗口管理软件仍可能影响显示。请记录触发动作及相关版本，并通过 Issue 反馈。

### 如何升级本地构建

先右键退出应用，再更新源码并运行 `./build.command`，最后重新打开应用。应用标识保持不变时，保存的位置会继续使用。
